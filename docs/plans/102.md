# Issue 102: Dashboard Risk Card Top-N Distribution (Chart)

## Objective
Enhance the existing live Dashboard Risk card to support Top-3/Top-5 concentration distribution with a chart-first UI, while keeping the feature fully driven by current `/dashboard/summary` payload fields (`top_holdings`, `net_worth.total`) and avoiding backend changes.

## Critical Ambiguity Check
No critical ambiguity blocks planning or implementation.
Non-critical product questions are listed in the Open Questions section with proposed defaults.

## Architecture Decisions
1. Frontend-only change
- Keep all Top-N concentration logic in the web layer.
- Do not add or modify backend endpoints.
- Rationale: required data is already present in `DashboardSummary`.

2. Deterministic pure risk helpers
- Extend `web/src/lib/risk.ts` with pure, testable Top-N functions.
- Avoid introducing data transforms directly inside JSX.
- Rationale: preserves deterministic behavior and makes calculations unit-testable.

3. Recharts for visualization
- Add `recharts` as a frontend dependency.
- Use a horizontal bar chart for Top-N distribution rows.
- Rationale: chart-first requirement with minimal integration complexity.

4. Stable Top-N behavior
- Add `selectedTopN: 3 | 5` state in Risk card, default `5`.
- Include `CASH` holdings in ranking and concentration.
- If holdings are fewer than selected `N`, show available rows and helper text.

5. Risk metric compatibility
- Keep existing largest-position metric and threshold behavior unchanged.
- Replace fixed Top-5 metric with selected Top-N metric while preserving existing state-color mapping (`muted` / `good` / `warn` / `bad`) for concentration output.

6. Minimal-diff file strategy
- Keep Risk UI in `web/src/App.tsx` (no broad dashboard refactor).
- Add only scoped CSS classes in `web/src/App.css`.
- Keep existing API types unchanged in `web/src/lib/api.ts`.
