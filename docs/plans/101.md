# Issue 101: Replace Mocked Dashboard Risk Card With Live Data

## Problem
The dashboard Risk card in `web/src/App.tsx` is hardcoded:
- Largest position is fixed (`ETH — 14.2%`)
- Top 5 concentration is fixed (`48.6%`)
- Card explicitly says `Mocked`

This is misleading because live holdings data already exists in `/dashboard/summary` (`top_holdings`, `net_worth.total`).

## Goal
Make the Risk card fully data-driven from existing dashboard payload fields without backend contract changes.

## Architecture Decisions
1. Frontend-only implementation
- Keep computation in web layer using already-fetched `DashboardSummary`.
- Do not add new backend endpoints for this issue.

2. Deterministic pure calculation helpers
- Add a small pure helper module (example: `web/src/lib/risk.ts`) to compute:
  - largest position display payload
  - top-5 concentration percent
  - threshold state flags (warn/in-band/out-of-band)
- Rationale: isolates math from JSX, easier to unit test, avoids hidden UI-side logic drift.

3. Keep existing API type contract
- Reuse `DashboardSummary.top_holdings[]` and `DashboardSummary.net_worth.total`.
- Do not modify OpenAPI, request params, or backend response fields.

4. Minimal-diff UI strategy
- Keep Risk card in `web/src/App.tsx` (no broad dashboard refactor).
- Replace only hardcoded values/copy and move literals to constants.

## Ambiguity Resolution
1. Holdings universe for Risk card
- Include `CASH` assets from `top_holdings` in both largest position and top-5 concentration.
- Rationale: card is explicitly based on existing `top_holdings` + `net_worth.total` payload, with no backend contract change.

2. Definition of “insufficient data” for Top 5
- Treat top-5 concentration as insufficient when holdings count is fewer than 5, or when `net_worth.total <= 0`.
- UI behavior for insufficient: render `0.0%` in muted/no-data state.
